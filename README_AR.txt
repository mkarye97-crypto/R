MOODY QUREO — Requests Edition
================================

النسخة دي بتستخدم requests بدل Playwright، وبتشتغل بتسجيل دخولك أنت.

الموجود:
- تسجيل دخول من بوابة QUREO ثم تأكيد الجلسة من خادم الدراسة.
- تحميل بيانات القسم والفصول من API مباشرة.
- تخطي الفصول والمحاضرات المكتملة بالفعل.
- فتح المحاضرة، قراءة بياناتها، وإرسال قيمة talk فقط لو الـ API رجّع حقل value صراحةً.
- إرسال طلب إكمال المحاضرة ثم قراءة الحالة مرة أخرى للتأكد.
- حفظ تقرير التشغيل والردود التشخيصية داخل data/.
- إيقاف آمن عند فشل API أو عدم تأكيد الاكتمال.

غير الموجود / مقفول عمدًا:
- لا يرسل إجابات اختبارات أو مراجعات.
- لا يبدأ الاختبار ولا يقدمه.
- لا يختار أول اختيار عند غياب الإجابة.
- لا يستخدم cookies.json أو أي جلسة من ملف خارجي.
- لا يحفظ كلمة المرور أو Cookies أو Tokens في ملفات المشروع.

التشغيل على Windows:
1) ثبّت Python 3.10 أو أحدث.
2) افتح CMD داخل المجلد.
3) نفّذ:
   py -m pip install -r requirements.txt
   py main.py

التشغيل على Termux:
1) pkg update && pkg install python
2) cd إلى مجلد المشروع.
3) python -m pip install -r requirements.txt
4) python main.py

تشغيل مستويات محددة:
python main.py --from-level 5 --to-level 12

ملاحظات مهمة:
- اكتب Login ID وكلمة المرور عند الطلب. كلمة المرور لا تظهر أثناء الكتابة.
- لازم يكون الحساب مخولًا للدخول إلى دورة javascript_ar والقسم 5.
- إذا ظهر prev_chapter_not_completed أو خطأ صلاحية، البرنامج يتوقف ولا يحاول تجاوز شرط المنصة.
- مسارات API مبنية على التقاطات HAR بتاريخ 2 نوفمبر 2026، وقد تتغير من المنصة.
- نجاح HTTP وحده لا يثبت اكتمال الدرس؛ لذلك البرنامج يعيد قراءة الحالة.
- لا يمكن ضمان العمل على كل حساب قبل تجربة تسجيل الدخول على حسابك؛ لا توجد بيانات دخول ضمن الحزمة.

الخصوصية:
لا تشارك ملفات data/ أو HAR أو لقطات تحتوي على Cookies أو Authorization أو بيانات حسابك.

تحديث تحليل الاتصال:
- كل طلبات API التعليمية وردودها المنقحة تُحفظ في data/api_traffic_audit.jsonl.
- لتحليل السجل بعد التشغيل: python analyze_traffic.py
- التفاصيل وحدود التشخيص في TRAFFIC_ANALYSIS_AR.txt.
- التسجيل لا يلتقط حركة التطبيقات الأخرى ولا يكشف الإجابات الصحيحة تلقائيًا.
